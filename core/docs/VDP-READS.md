# VDP read-side candidate

`waterbox\gens_vdp_read.c` ports the pinned `vdp_io.asm` data, status,
horizontal-counter, and vertical-counter reads. It also reproduces the
horizontal-counter table generated by `Reset_VDP`. It is not a VDP
renderer, control-port writer, register setter, DMA engine, or complete
reset implementation. It has not been compiled or run natively.

`GensVdpRead` references the original machine's state instead of maintaining
a second copy. Supply 64 KiB VRAM, the actual 256-byte CRAM and VSRAM
backings, the 1024-byte horizontal-counter table, and pointers to the
corresponding globals. The pinned assembly declarations and C header
disagree about some array sizes. Do not infer the emulated layout from the
header alone. All storage, configuration, and callbacks must remain stable
and guest-owned and follow snapshot rules.

Generate a new table with `gens_vdp_h_counter_init` when the original would
reset it. Both table columns use the original fixed divisor 488, including
in PAL mode. Counter reads use the caller's actual `CPL_M68K` and
`Cycles_M68K`. Do not replace the table divisor with a regional cycles-per-line
estimate or regenerate the table on every read.

## Observable state changes

Data reads clear only the low byte of `Ctrl.Flag`. Accesses 5, 6, and 7
read VRAM, CRAM, and VSRAM respectively, using the original even-address
masks. They increment only the low 16 bits of `Ctrl.Address`, preserving
its upper half. Other access modes within the original 16-entry table
return zero without incrementing the address. An index outside that table
fails after clearing the latch byte instead of reading outside the table.

Status reads return the old low status word and apply the original status
toggle and flag-clearing masks to the stored low word. The upper half of
`VDP_Status` is preserved. Display-off adds bit 3 to the returned word,
not the stored status. These reads do not clear `Ctrl.Flag`.

Counter reads query the 68000 odometer, then read the current line-cycle
targets and register values. Their arithmetic wraps at 32 bits and the
phase wraps at 512 entries. Horizontal mode selection uses `Set4 & 0x81`,
not just bit zero. Vertical folding depends on the PAL bit in
`VDP_Status`, not a separate region preference. It preserves the original
thresholds, horizontal advance window, interlace byte rotation, and
full-register behavior for noncanonical line values.

## Device adapters

`gens_vdp_genesis_read` is compatible with the Genesis bus read callback.
It preserves byte/word port dispatch and the mapper-selected VDP handler
at lower physical addresses. A word HV read calls V then H and queries
the odometer separately for each. It does not collapse them to one
timestamp.

`gens_vdp_z80_read` supplies raw status words and counter results to the
68000-facing Z80 window. That window retains responsibility for its own
byte-handler status selection, including the word-access quirk.

`gens_vdp_native_read` implements the status and counter operations of the
native Z80 handler backend. It preserves the original `ECX` and `EDX`
values. Status changes only `AX`, while counters reproduce the original
`EAX` result. The pinned Starscream odometer implementation itself changes
only `EAX`. This supplies a real read-only VDP backend without pretending
to implement the unrelated sound, write, or banked 68000 operations.

Machine routing must still dispatch other devices to their own backends.
The shared `GensVdp` configuration and optional Genesis bus `vdp` field
connect these reads to the same storage used by writes and DMA. Its Z80
wrappers expose that storage without replacing unrelated device callbacks.
See `VDP-WRITES.md` for initialization and lifetime requirements.
The odometer callback must use the live 68000 CPU timing, not wall time,
Z80 cycles, or an arbitrary line counter. Missing or failed required
callbacks return failure, which the outer Genesis bus reports as a backend
error. Earlier side effects are not rolled back. Combined counter reads
leave the output unchanged if either callback fails.

## External comparison

`compile vdp-read-check` compares extracted, unchanged i386 read routines
with the candidate x86-64 code. Four trace digests cover all generated
counter-table bytes, representative data modes and addresses, every low
status word in both display states, and horizontal/vertical modes across
all phases and selected normal and noncanonical lines. Its native-only
checks also exercise Z80-window and native-handler integration, missing
callbacks, and failures during a combined read. A changed table byte is
the negative control.

The reference initializes only the extracted table loop, not the complete
original VDP. Its odometer is synthetic. The command has not been run,
does not execute a CPU or render a frame, and does not establish game or
movie synchronization.
