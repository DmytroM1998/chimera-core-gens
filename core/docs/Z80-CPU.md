# Z80 CPU core

`waterbox\gens_z80_cpu.c` is a complete C port of the pinned `z80.asm` as
Gens builds it (`GENS_OPT` 1, `Z80_SAFE` 0). It mirrors the original public
API: init, reset, handler ranges, odometer, `exec`, interrupt and NMI, and the
PC and AF getters and setters.

## Verification

`tests\test_z80_diff.c` links the unchanged `z80.asm`, assembled as i386, and
the C port into one 32-bit program. Each scenario creates random code, RAM,
I/O memory, registers, interrupt mode and pending interrupt or NMI. It then
runs both cores with the same odometer targets over several rounds. Some
scenarios raise interrupts from inside a write handler, others fetch code from
Z80 RAM to cover self-modifying code. After every round it compares every
register, the X/Y flag copies, IFF, IM, interrupt state, status, odometer,
PC, all RAM, all handler-visible memory and the ordered handler access log.

On Windows with Zig's clang and NASM 2.16.03, three seeds of 20,000 scenarios
gave 51,002 complete matches and no mismatch. The other scenarios are counted
separately for the two cases below. A negative control that flips one flag
bit in the port is detected.

`docker compose run --rm compile z80-cpu-check` runs the same comparison on
Linux with `gcc -m32`. It also regenerates the tables and checks a negative
control.

## Dispatch tables

`waterbox\gens_z80_tables.c/.h` are generated by `tools\generate_z80_tables.py`
from the opcode tables and the `INC`, `DEC` and `DAA` flag tables in `z80.asm`.
Every entry of all seven opcode tables is classified, and none is left
unimplemented. The tables keep the original quirks, for example `DD 1C` maps
to `DEC E`, `DD FC` maps to `CALL P` instead of `CALL M`, and unused `ED`
opcodes act as a one-byte `NOP`. A Python test and `z80-cpu-check` fail when
the committed tables differ from the source.

## Original quirks that are reproduced

- `RETN` and `RETI` do not restore IFF1, because the original's IFF1 alias
  points at IFF2.
- `SLL B` to `SLL E` store the shifted value without the low bit. `SLL A`,
  `SLL H`, `SLL L` and the memory forms store it with the low bit.
- `RLD` ORs A's high nibble into the memory byte.
- Port input reads zero and `IN A,(n)` leaves A unchanged. Port output does
  nothing.
- `CP A`, `CP H` and `CP L` copy the opcode byte into the X/Y flag copy.
- `BIT 3` and `BIT 5` on memory copy bits 8 to 15 of the ECX register after the
  access into the X/Y flag copy. For RAM this is `(address & 0x1fff) >> 8`.
  A handler may report its final ECX value in `io_ecx`. The Gens handlers
  modify ECX, so the machine adapter must set it from their register model.
- At the end of a run, the original adds the remaining cycles to the odometer
  when bit 1 of EDX is set. EDX holds the pending interrupt cycle count, the
  status after `HALT`, or a value left by an interrupted block instruction. The
  port tracks that value for every exit path.
- Conditional `RET` costs 17 cycles when taken, and block instructions repeat
  with 21 cycles per extra iteration and resume at the same instruction.
- `DI` and `EI` run the next instruction without a cycle check. `EI` defers the
  interrupt check until after it.

## Deliberate differences

- `DAA` with the H flag set: the original adds H as a 0x1000 byte offset, past
  its 2048-word table, and reads whatever the original executable linked after
  it. The port uses the table's H half at word 0x400, which is what the table
  layout intends, and increments `daa_overflows`. A sound driver that relies on
  this may desynchronize. The counter lets tools report it.
- Execution that runs past the end of the 8 KiB RAM reads unrelated memory in
  the original. `GENS_Z80_RAM_SIZE` reserves 0x100 spare bytes after RAM. In Gens
  the first four are the `Bank_Z80` register, which the machine must alias.
- Handlers receive the `GensZ80` pointer instead of a fastcall register
  argument. The caller's context lives in `opaque`.
- `gens_z80_exec` returns zero instead of leftover register contents when the
  CPU was halted at entry. Gens never reads that value.
- Fetch regions are pointer-width host addresses and must outlive the CPU.
  They are not part of any saved state.

`trace` is an optional per-instruction hook at the same points as the original
`GENS_LOG` hook. The fuzzer uses it to locate divergences.
