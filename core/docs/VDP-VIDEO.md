# Genesis screen conversion

`waterbox\gens_vdp_video.c` ports `Render_MD_Screen`, converting the
intermediate `Screen_16X` values through the original 32768-entry lookup
tables into 16-bit and 32-bit `MD_Screen` backings. It does not generate
scroll/sprite pixels or provide Chimera video exports.

`GensVdpVideo` references the guest-owned 336-by-240 source and destination
buffers, lookup tables, row-offset table, visible-line count, current-line
global, and register 12. Use the same destination buffers as VDP reset and
the same lookup arrays generated by `gens_color_lookup_generate`.
Inputs must be CRAM-resolved words, not the draft palette-slot metadata
produced by row composition. See `VDP-PIXELS.md` for that preceding stage.
Configuration and distinct backing addresses must remain stable under
snapshot rules.

## Physical layout and preserved effects

The pinned renderer's `TAB336` contains 240 dwords, despite the old C header
declaring 336 platform-sized `unsigned long` entries. The candidate uses
explicit 32-bit offsets. `gens_vdp_video_rows_init` initializes exactly the
original 240 offsets and leaves any supplied trailing storage untouched.

Conversion visits columns 8 through 335 of each visible row. It does not
clear the first eight columns, crop the buffer to the active width, or
clear inactive rows. Intermediate values are used as complete lookup
indices, including the upper `0x4000` bank. Removing those bits would lose
the lookup generator's original foreground/pink behavior.

After conversion, a second pass clears one marker pixel in each visible
row: column 328 if register 12 bit zero is set, otherwise column 264.
This intentionally differs from the `0x81` horizontal-width test used by
the register setter. It is not replaced with clearing a whole right border.

The current-line global ends at the visible-line count. Zero or negative
visible-line counts follow the original empty-loop result and leave it at
zero without modifying pixels. Counts above the physical 240-row backing
are rejected.

`gens_vdp_video_convert` leaves the fake-screen flag alone.
`gens_vdp_video_render_screen` additionally clears its supplied
`FakeVDPScreen` byte before conversion, matching the normal frame caller.
The eventual frame backend must propagate failure instead of reporting a
completed frame.

Invalid row offsets fail before pixel conversion. Columns that `Render_Line`
did not resolve, past the 256 pixels of H32 mode, can hold raw values of
0x8000 and above. The original then reads past `Palette` and `Palette32`.
The port masks such an index to 15 bits. Those pixels are outside the active
display, so the visible picture is unaffected.

## External comparison

`compile vdp-video-check` compares the unchanged extracted C++ function
compiled for i386 and x86-64 against the candidate. The isolated reference
uses the original register declaration and actual 240-dword row backing.
It covers empty/negative, short, NTSC, and PAL line counts, all relevant
marker modes, full destination buffers, and raw/wrapped invocation.
A changed output pixel is the negative control.

Native-only cases cover invalid dimensions/offsets/indices, retained
borders and rows, and failure after partial conversion. They also connect
the real Genesis lookup generator to conversion and distinguish pink
lower-bank pixels from opaque upper-bank pixels.

The command has not been built or executed here. Source-level interpretation
does not establish native video output, gameplay, or movie synchronization.
Complete scanline composition and renderer/frame/backend integration remain
unimplemented.
